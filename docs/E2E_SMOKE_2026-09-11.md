# E2E / Smoke Test — 2026-09-11

## Overall verdict

**FAIL for real beta traffic; PASS for clickable prototype.**

## Deployment
- PASS: Netlify production deploy is READY.
- PASS: deploy tracks `main` and commit `e612f9851c32195959cd6625d3cae4a438cd3d48`.
- PASS: HTTPS endpoint exists at `https://platt-beta.netlify.app`.

## Public marketplace
- PASS: start page, search/filter controls and profile cards are present.
- PASS: demo data provides visible content while database is empty.
- FAIL: database currently has 0 auth users, 0 accounts, 0 listings and 0 inquiries; therefore no public flow reaches a real provider.
- FAIL: inquiries on demo profiles show a success-like demo toast but are not persisted.
- FAIL: first two result cards are always labeled `Sponsored` regardless of actual campaign state.
- WARN: direct profile URLs can bypass the 18+ gate; age gate exists only on the home page.
- WARN: footer legal labels are text only; no real Impressum/Datenschutz/Jugendschutz/Meldestelle routes exist.
- WARN: inquiry form lacks a privacy notice/consent context.

## Provider dashboard
- FAIL for real beta use: no authentication or account binding.
- FAIL: metrics, inquiries and credits are demo-only.
- FAIL: Boost only changes browser state and resets on reload.
- FAIL: sidebar entries and profile editing are not implemented.

## Admin
- FAIL for real beta use: admin page is publicly reachable and unauthenticated.
- FAIL: moderation queue and metrics are demo-only.
- FAIL: moderation actions only show demo toasts.

## Mobile / UX
- FAIL: pricing section has an inline 3-column grid that overrides responsive CSS and is cramped on phones.
- WARN: mobile header keeps both Dashboard and Anbieter-Login visible and is likely too wide around 390px.
- WARN: dashboard/admin tables have no horizontal overflow wrapper.
- WARN: search inputs rely on placeholders instead of labels/ARIA labels.

## Backend / security
- PASS: public `listings` SELECT works under the anon role and RLS limits it to active rows.
- PASS: frontend uses a Supabase publishable key, not a secret service key.
- WARN: all business tables are empty, so the full request path cannot yet be exercised end-to-end.
- WARN: `listing_media`, `availability` and `reports` have RLS enabled but currently no policies; they are therefore blocked rather than exposed.
- WARN: public inquiry INSERT has no anti-spam/rate-limit layer.
- WARN: remote listing fields are inserted into `innerHTML` without escaping, creating a stored-XSS risk once provider-entered data goes live.
- WARN: no Netlify security headers/CSP are configured.

## Supabase performance advisor
- 8 foreign keys lack covering indexes.
- 8 RLS policies repeatedly evaluate `auth.uid()` per row and should use `(select auth.uid())` at scale.
- `listings` has multiple permissive SELECT policies.

## Beta gate before real external users
1. Create at least one real authenticated provider + active listing and test inquiry persistence.
2. Protect Dashboard/Admin with authentication and role checks.
3. Add policies for media/availability/reports.
4. Fix mobile pricing/header/table layout.
5. Remove fake Sponsored labels and use campaign state.
6. Escape/sanitize remote profile content.
7. Add legal/privacy routes and inquiry privacy notice.
8. Add rate limiting / anti-spam for inquiries.
9. Add baseline security headers/CSP.
